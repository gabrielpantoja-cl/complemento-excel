## 4. Step-by-step plan

### Step 4.1 — Create `opencode.json`

**Exact path:** `opencode.json` at repo root.

**Content (draft):**

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "minimax-coding-plan/MiniMax-M3",
  "enabled_providers": ["minimax-coding-plan"],
  "share": "disabled",
  "permission": {
    "edit": "allow",
    "read": {
      "*": "allow",
      "*.env": "deny",
      "*.env.*": "deny",
      "*.env.example": "allow"
    },
    "glob": "allow",
    "grep": "allow",
    "bash": {
      "*": "ask",
      "git *": "allow",
      "npm *": "allow",
      "node *": "allow",
      "ls *": "allow",
      "head *": "allow",
      "tail *": "allow"
    },
    "webfetch": "ask",
    "websearch": "ask",
    "external_directory": "ask",
    "doom_loop": "ask",
    "skill": { "*": "allow" }
  }
}
```

**Rationale (one line each):**
- `$schema` — editor picks up mistakes as you type.
- `model` — pins the only model the user has; no ambient resolution.
- `enabled_providers` — closes off the 75+ default providers; only this one
  provider is loadable.
- `share: "disabled"` — no auto-share of sessions to opencode.ai.
- `edit: "allow"` — opencode is the dev's tool; no need to gate edits.
- `read` — default `allow` plus explicit `.env*` deny (defence-in-depth alongside
  `.gitignore`).
- `bash` — broad `ask` with narrow `allow` for the everyday dev commands
  (`git`, `npm`, `node`, `ls`, `head`, `tail`). Anything else prompts.
- `webfetch` / `websearch` — `ask` per default-deny methodology.
- `external_directory` / `doom_loop` — `ask` (opencode's default, made explicit).
- `skill: "*": "allow"` — explicit so all loaded skills are discoverable.

**Validation (before saving):**

1. Fetch `https://opencode.ai/config.json` and confirm shape compatibility for
   each top-level key used (`$schema`, `model`, `enabled_providers`, `share`,
   `permission`).
2. Validate JSON parses: `node -e "JSON.parse(require('fs').readFileSync('opencode.json','utf8'))"`
   in the repo root.

**Validation (after saving):**

3. `opencode` should start without `ConfigInvalidError`. Manual user check — log
   this requirement in the journal.
4. `npm run check` passes (no source touched, so trivially should).

### Step 4.2 — Patch `.gitignore`

**Edit type:** append lines (no removals).

**Add after the existing `/*.pdf` line:**

```gitignore
# Local env variants (keep .env.example tracked via the negation below)
.env.*
!.env.example

# IDE / build artefacts
.vscode/
.idea/
*.tsbuildinfo
*.log
coverage/
```

**Rationale:**

- `.env.*` covers `.env.local`, `.env.development`, `.env.production`, etc.
- `!.env.example` is the standard "negation" pattern — gitignore's last-matching
  rule wins, so this re-allows `.env.example`.
- `.vscode/` and `.idea/` are per-user IDE state.
- `*.tsbuildinfo` is TypeScript incremental build cache.
- `*.log` is generic.
- `coverage/` covers any future test coverage tooling.

```markdown
# Migration: 2026-07 — opencode config bootstrap

## Type
Additive config + doc augmentation. No source changes.

## Why
Audit found zero `opencode.json` and zero explicit permissions; opencode was
running with wide-open defaults (75+ providers reachable). Pinning the model,
narrowing the provider list, and adding tight permission rules brings the
tooling to current best-practice without touching the add-in build.

## What changed
- Added `opencode.json` with `$schema`, `model`, `enabled_providers`,
  `share: "disabled"`, and tightened `permission` block.
- Hardened `.gitignore` with `.env.*` (and `!.env.example`), `.vscode/`,
  `.idea/`, `*.tsbuildinfo`, `*.log`, `coverage/`.
- Added Skills / Agents / Commands / Models sections to AGENTS.md.

## What did NOT change
- No files in `src/` were modified.
- `skills/` at repo root was not moved.
- No custom agents / commands / skills were created.
- No junctions or symlinks.
- No global opencode config touched.

## Lessons learned
- The fork's `skills/` directory is consumed by `src/skills/catalog.ts` via
  `import.meta.glob` and is NOT in any of opencode's 6 canonical paths.
  This is a known and intentional divergence from upstream; it lets the add-in
  bundle skills at build time without requiring them to be in the agent
  context. Accepting the split for now.
- opencode v1.18.1 (released 2026-07-14) is the target version. No deprecated
  keys needed migration (no existing config to migrate).

## Open follow-ups
- Decide whether to wire `skills.paths: ["skills"]` into `opencode.json` so
  opencode's `skill` tool also lists the fork's bundled skills.
- If a public docs URL for `minimax-coding-plan/MiniMax-M3` surfaces, update
  the Models section in AGENTS.md.
- If a custom agent or command is added, update the corresponding AGENTS.md
  section.

## Related docs
- [research-2026-07-14.md](../research-2026-07-14.md)
- [plan-2026-07-14.md](../plan-2026-07-14.md)
```

## 7. Rollback procedure

**Before commit (safe restore):**

```bash
# From repo root, with no other in-flight changes:
rm opencode.json
rm docs/ai-strategy/migrations/2026-07-opencode-config-bootstrap.md
git restore .gitignore AGENTS.md
```

**After commit (via git revert):**

```bash
git revert <commit-sha>   # creates a new commit that undoes the change
git push origin main
```

**Hard reset (last resort, only if revert isn't viable):**

```bash
git reset --hard <commit-sha-preceding-the-change>
git push --force-with-lease origin main
```

`<commit-sha-preceding-the-change>` is the commit immediately before the
opencode-config-bootstrap commit.
