### 1.3 Skill discovery paths (canonical order)

Per `docs/skills`, opencode loads `**/SKILL.md` from all of:

1. `.opencode/skills/<name>/SKILL.md` *(project, canonical)*
2. `~/.config/opencode/skills/<name>/SKILL.md` *(global)*
3. `.claude/skills/<name>/SKILL.md` *(project, Claude-compat)*
4. `~/.claude/skills/<name>/SKILL.md` *(global, Claude-compat)*
5. `.agents/skills/<name>/SKILL.md` *(project, agent-compat)*
6. `~/.agents/skills/<name>/SKILL.md` *(global, agent-compat)*

Plus extra paths registered under `skills.paths` / `skills.urls` in `opencode.json`.

Skill frontmatter rules (strict, from `docs/skills`):

- `name` required, 1–64 chars, lowercase alphanumeric + single hyphens, matches folder, no leading/trailing/consecutive hyphens
- `description` required, 1–1024 chars, must cover both *what* and *when*
- Optional: `license`, `compatibility`, `metadata` (string→string)
- Unknown frontmatter fields are silently ignored
- Permissions: `skill` key with `"*"` / pattern → `"allow" | "ask" | "deny"`

### 1.4 MCP server config (current shape)

- `mcp[name].type` is **required** — `"local"` or `"remote"`
- `mcp[name].command` is an **array of strings** (not a single string)
- `mcp[name].timeout` is per-server, in ms, default 5000
- `enabled: false` cleanly disables inherited servers
- Header values support `{env:VAR}` interpolation; `${VAR}` is **not** substituted

There is no deprecated single-number `timeout` syntax in v1.18.1 — the per-server `timeout` field is the only form. (Legacy `experimental.mcp_timeout` still works as a global default.)

### 1.5 Permission defaults (worth knowing for the audit)

- Most permissions default to `"allow"`.
- `doom_loop` and `external_directory` default to `"ask"`.
- `read` defaults to `"allow"`, but `.env*` files are denied by default.
- Per-pattern rule lists: **last match wins** — broad rules go first, narrow rules last.

### 1.6 Windows + opencode specifics

- Windows is supported via `scoop` / `choco` / npm. WSL is the documented recommendation.
- For repo retrocompat paths, **junctions** (`New-Item -ItemType Junction`) work without admin/dev-mode and are filesystem-level. Symlinks need admin or dev-mode on Windows.
- Junction targets are resolved by opencode's path walk — the loader follows them like normal directories.

## 4. Provider / config hygiene rules from the methodology

Re-stated to keep them top-of-mind for the audit:

- `enabled_providers` / `disabled_providers` are *huge* lever items — default opencode ships 75+ providers via `models.dev`. If we do nothing else, we should at minimum set `enabled_providers` to a tight allow-list.
- MCP servers need explicit `timeout` (ms) — never the deprecated single-number syntax.
- `.gitignore` must cover `.env`, `.env.*`, any local credential files, and any `dist/` / build outputs the AI shouldn't see.
- Per-agent `permission` is preferable to top-level `permission: "allow"` shorthand.
